# 실감 모션 (Realistic Motion)

모션의 목적은 꾸밈이 아니라 **물체가 실제로 거기 있다고 믿게 만드는 것**이다. 사람은 무게·관성·마찰을 평생 봐 왔기 때문에, 물리를 어긴 움직임은 0.1초 만에 "가짜"로 읽는다. 이 스킬은 그 믿음을 만드는 규칙과, 이 저장소에 이미 만들어 둔 부품, 그리고 "됐다"를 숫자로 증명하는 검증 절차다.

## 0. 먼저 할 일

1. `components/motion/tokens.ts`를 읽는다. 스프링·이징·지속시간 숫자는 **여기서만 고른다.** 새 숫자가 필요하면 근거(ζ, 정착 시간)를 주석으로 달아 토큰에 추가한다. 컴포넌트에 `stiffness: 300` 같은 즉흥 숫자를 쓰지 않는다.
2. 아래 표에서 이미 있는 부품으로 해결되는지 본다. 되면 새로 만들지 않는다.
3. 작업 뒤에는 6장의 검증을 반드시 돌린다. 눈으로 "부드러워 보인다"는 검증이 아니다.

## 1. 부품 목록 (`components/motion/`)

| 부품 | 쓰는 곳 | 핵심 물리 |
|---|---|---|
| `CinematicHero` | 상세 히어로 사진 | 셔터(clip-path 4%→0) + 렌즈 정착(1.14→1배, 1.6s) + 스크롤 시차(사진은 22%만 이동, 1.08배, 어두워짐) |
| `MaskReveal` | 큰 제목 | 어절 단위로 마스크 아래에서 밀어 올림. 한글은 띄어쓰기 단위로만 쪼갠다 |
| `CountUp` | 스펙 숫자(면적·기간·수량) | 과감쇠 스프링(ζ≈1.29). 숫자는 오버슈트 금지. SSR에서는 최종값 |
| `BeforeAfter` | 시공 전·후 비교 (`compare` 콘텐츠 블록) | 드래그 1:1, 탭 점프(snap), 놓을 때 속도 이어받는 관성(최대 22%), 첫 노출 때 한 번 흔들어 조작 가능함을 알림 |
| `DepthPhoto` | 카드 사진 | 액자 고정, 안쪽 사진만 포인터 반대로 ±2.2% + 반사광. 정밀 포인터 기기에서만 |

상세 페이지 연결 지점: `ProjectDetail.tsx`의 히어로·h1·`SpecGrid`·`ContentBlockRenderer`(`compare`), `ProjectCard.tsx`의 사진. 전체를 한 화면에서 만져 보는 곳: `/motion-lab`.

`compare` 블록 데이터 형식:
```json
{ "type": "compare", "id": "before-after", "heading": "시공 전과 후",
  "before": { "src": "…", "alt": "시공 전 마당. 배수 불량으로 잔디가 죽은 상태" },
  "after":  { "src": "…", "alt": "시공 후. 투수 포장과 그라스 식재" },
  "caption": "같은 위치, 같은 화각에서 촬영", "aspectRatio": "3 / 2" }
```
**같은 자리·같은 화각의 실제 전후 사진만 넣는다.** 다른 현장 사진을 전후로 붙이면 시공 사례 기록을 조작하는 것이 된다.

## 2. 물리 원칙 — 숫자를 고르는 법

**스프링은 감쇠비 ζ = c / (2√(k·m))로 성격이 정해진다.**
- ζ < 1 (지나쳤다 돌아옴): 가벼운 것. 하트, 핀, 핸들 눌림 → `SPRING.leaf`
- ζ ≈ 1 (지나치지 않고 가장 빨리 멈춤): 면적과 무게가 있는 것. 카드, 패널, 사진 → `settle`, `soft`, `follow`
- ζ > 1 (스며듦): 정보 값. 숫자, 진행률 → `count`
- 정착 시간 ≈ 4 / (ζ·√(k/m)). 큰 면은 0.3~0.4s, 작은 UI는 0.2s 안팎.

**무게는 크기에 비례한다.** 화면을 덮는 사진이 버튼처럼 0.2s에 튀어 오르면 종이처럼 보인다. 면적이 클수록 `DUR`를 길게, 스프링을 부드럽게.

**들어올 때는 감속(`EASE.out`), 나갈 때는 가속(`EASE.in`)에 들어올 때의 60~70% 시간.** 사라지는 것을 오래 보여줄 이유가 없다.

**시차(parallax)는 거리감이다.** 먼 것은 느리게. 배경 사진은 스크롤의 20~25%만 움직인다. 50%를 넘기면 멀미가 난다.

## 3. 직접 조작 원칙 — 손에 붙어야 한다

1. **드래그 중에는 스프링을 끈다.** `motionValue.set()`으로 손가락에 1:1. 따라오는 데 스프링을 쓰면 고무줄이다.
2. **놓는 순간 속도를 이어받는다.** 최근 이동의 지수 평균(`v = v*0.6 + 순간속도*0.4`)으로 속도를 재고, 80ms 이상 멈췄다 놓았으면 0으로 본다. 그 속도를 `animate(mv, 목표, { ...SPRING.soft, velocity })`에 넘긴다.
3. **이동량에 상한을 둔다.** 세게 던져도 끝까지 날아가면 통제를 잃은 느낌이다(`INERTIA.maxTravel`).
4. **탭은 순간이동이 아니라 짧은 미끄러짐**(`SPRING.snap`).
5. **스크롤을 빼앗지 않는다.** 가로 조작 요소는 `touch-action: pan-y`.
6. **조작 가능함을 한 번만 보여준다.** 첫 노출 때 살짝 흔들고, 사용자가 먼저 만지면 생략.

## 4. 구현 규칙 — 실제로 터졌던 버그에서 나온 것

- **한 요소에 transform 책임은 하나.** Framer가 `scale`/`x`를 쓰면 Tailwind의 `-translate-x-1/2`가 덮여 사라진다(비교 슬라이더 핸들이 선에서 22px 어긋났던 원인). 위치는 바깥 일반 요소, 움직임은 안쪽 `motion` 요소로 나눈다. 로드 애니메이션과 스크롤 연동도 겹을 나눈다(`CinematicHero`의 3겹 구조).
- **모션 감축이어도 마크업 구조를 바꾸지 않는다.** `if (reduce) return <>{text}</>`처럼 구조를 바꾸면 서버 렌더와 달라져 하이드레이션 오류(React #418)가 난다. 같은 구조에 `initial={reduce ? false : …}`로 움직임만 끈다.
- **SSR에서 최종 상태가 보이게.** 숫자·제목은 JS 없이도 읽혀야 한다. 시작값으로 내리는 건 페인트 전(`useLayoutEffect`)에.
- **transform·opacity·clip-path·filter만 애니메이션한다.** `width/height/top/left/margin`은 매 프레임 레이아웃을 다시 계산한다. 폭이 바뀌는 효과는 `clip-path: inset()`이나 `scaleX`로.
- **숫자 폭 고정.** `tabular-nums` + 최종 글자 수만큼 `min-width`. 자릿수가 바뀔 때 옆 글자가 흔들리면 싸구려로 보인다.
- **포인터 효과는 정밀 포인터에서만.** `(hover: hover) and (pointer: fine)`. 터치에서 기울기·시차는 손가락이 가리고 스크롤과 싸운다.
- **움직이면 안 되는 것은 분리.** 사진과 함께 배지가 흔들리면 안 된다(`DepthPhoto`의 `overlay`).
- **화면낭독기.** 쪼갠 글자는 `aria-hidden`, 원문은 `sr-only` 한 번. 조작 요소는 `role="slider"` + 키보드(←/→, Shift, Home/End).

## 5. 하지 말 것

- 모든 섹션에 같은 fade-up을 거는 것. 장면마다 역할이 다른 움직임 하나면 충분하다.
- 무한 반복(둥실둥실, 반짝임). 정보를 읽는 동안 눈을 빼앗는다.
- 스크롤 하이재킹(스크롤 속도·방향 바꾸기). 사용자는 스크롤을 자기 손의 연장으로 느낀다.
- 300ms 넘는 버튼 반응. 누른 즉시 반응이 시작돼야 한다(눌림은 100ms 안).
- 이유 없는 3D 회전. 글자가 기울면 읽기 나빠진다.

## 6. 검증 — "부드러워 보인다"가 아니라 숫자로

`next build && next start` 뒤 Playwright로 다음을 수치 확인한다. 템플릿은 `references/qa-motion.mjs`.

| 항목 | 통과 기준 |
|---|---|
| 히어로 | t≈0에 `clip-path: inset(4%)`, 1.8s 뒤 `inset(0%)`. 300px 스크롤 시 사진 translateY > 0, scale > 1 |
| 카운트업 | 표본 값이 단조 증가, 최종값과 정확히 일치, 한 번도 넘지 않음 |
| 비교 슬라이더 | 드래그 중 `aria-valuenow`가 포인터 위치와 같음(지연 0). 빠르게 던지면 놓은 위치보다 더 가되 maxTravel 이내. End=100, Shift+← = −10. 핸들 중심 x가 분할선 x와 같음(오차 1px 이내) |
| 깊이 사진 | 포인터를 모서리에 두면 안쪽 사진 transform에 scale 1.06과 반대 방향 이동 |
| 모션 감축 | `reducedMotion: 'reduce'`로 열었을 때 콘솔 오류 0(특히 React #418), 제목·숫자가 즉시 최종 상태 |
| 콘솔 | 오류 0 (외부 이미지 로드 실패는 샌드박스 네트워크 탓이면 제외하고 따로 보고) |

**주의:** 빌드를 다시 하면 이전 `next-server` 프로세스를 반드시 종료하고 새로 띄운다. 이전 서버가 남아 있으면 옛 HTML이 새 청크를 못 찾아 하이드레이션이 통째로 안 되고, 모든 모션이 "멈춘 것처럼" 측정된다.

## 7. 새 부품을 만들 때

1. 실제 물체 하나를 정한다(셔터, 렌즈, 종이 카드, 창문 너머 풍경, 문틀에 걸린 커튼). 그 물체의 질량과 마찰을 토큰으로 옮긴다.
2. 겹을 책임별로 나눈다(위치/로드/스크롤/포인터).
3. 모션 감축·SSR·키보드·터치를 처음부터 넣는다. 나중에 붙이면 구조가 바뀌어 하이드레이션이 깨진다.
4. `/motion-lab`에 한 칸 추가하고, 6장의 표에 통과 기준 한 줄을 추가한다.
