# 영상 모션 (Video Motion)

영상 속 글자는 **읽히는 시간 안에 의미를 전달하고 사라지는 물체**다. 이 스킬은 (1) 어떤 엔진으로 만들지, (2) 글자를 어떻게 움직일지, (3) 실사 영상과 어떻게 합칠지, (4) 소리·박자와 어떻게 맞출지, (5) 다 됐다는 걸 어떻게 증명할지를 다룬다.

- 실제 예제: 저장소의 `mg-shorts/` (Remotion, 매거진그린 브랜드 쇼츠). 새 영상은 여기서 복제해 시작한다.
- 세부 수치는 `references/`에 있다. 본문은 판단 기준만 담는다.
  - `references/text-motion.md` — 텍스트 모션 패턴 카탈로그(수치 포함)와 한국어 조판 규칙
  - `references/footage.md` — 실사 영상 + 자막·그래픽 합성, 컷 편집, 오디오 레벨, ffmpeg 레시피
  - `references/beat-sync.md` — 박자·가사·내레이션 동기화
  - `references/sources.md` — 출처 저장소와 라이선스(무엇을 베껴도 되고 무엇은 생각만 빌려야 하는지)
  - `scripts/qa_video.py` — 렌더 결과 자동 점검(프로브·첫 프레임·접촉 인화·컷 스트립·블랙/정지·라우드니스)

## 0. 시작 전 세 가지

1. **사실만 쓴다.** 화면에 나가는 숫자·인용·사례는 출처가 있는 것만. 목업 데이터(`data/projects/*.json`은 가상)를 실제 사례처럼 영상화하지 않는다. 예시가 필요하면 화면에 "예시"라고 적는다.
2. **매체를 정한다.** 매거진그린 = 사유와 여운(차분한 리듬, 세리프 제목, 오버슈트 거의 없음). 채널그린 = 해결사(훅 3초 → 해결 → CTA 하나, 더 빠른 리듬, 산세리프 중심, 분명한 강조). 둘을 섞지 않는다.
3. **대본이 먼저다.** 장면표(장면 / 화면 / 자막 / 길이)를 `mg-video-copy` 기준으로 먼저 확정하고 코드를 쓴다. 영상에서 가장 비싼 실수는 다 만든 뒤 문장을 바꾸는 것이다.

## 1. 엔진 고르기

| 상황 | 엔진 | 이유 |
|---|---|---|
| 텍스트·도형 중심 쇼츠, 브랜드 영상, 데이터 그래픽 | **Remotion** (`mg-shorts/`) | React로 조판, 프레임 단위 결정적 렌더, 이 저장소에 이미 세팅됨 |
| 실사 영상(인터뷰·현장) 위에 자막·그래픽 | Remotion에 영상 넣기 **또는** 그래픽만 알파로 렌더 후 ffmpeg 합성 | 길고 무거운 원본은 알파 오버레이 합성이 빠르고 안전 |
| 단순 컷 편집·무음 제거·자막 굽기·라우드니스 | ffmpeg 단독 | 렌더러가 필요 없다 |
| 웹페이지 화면을 그대로 담는 시연 | HTML + Playwright 프레임 캡처 + ffmpeg | 실제 화면이 증거 |

Remotion 주의: 직원 4명 이상 회사는 유료 라이선스 대상이다. 상업 배포 전에 확인한다. 이 작업 환경에선 Chrome 다운로드가 막혀 `REMOTION_CHROME`에 설치된 headless shell 경로를 넣는다(`mg-shorts/remotion.config.ts`).

## 2. 결정성 — 렌더는 "재생"이 아니라 "프레임마다 계산"

모든 엔진에서 공통이다. 프레임 N의 화면은 N만으로 정해져야 한다.

- 시간은 `useCurrentFrame()`(또는 `seek(t)`)에서만 얻는다. `Date.now()`, `performance.now()`, 타이머, rAF, CSS transition/animation 금지(렌더러는 CSS 애니메이션을 무시하거나 엉뚱한 순간을 찍는다).
- 난수는 시드 고정(해시 함수 또는 mulberry32). 그레인 같은 "살아 있는" 질감도 `seed = floor(frame/2)`처럼 프레임에서 만든다.
- 폰트는 로컬 파일(`public/fonts`)을 `FontFace`로 읽고 `delayRender`로 캡처를 막는다. 안 막으면 첫 프레임들이 대체 서체로 찍힌다. CDN 폰트는 렌더 서버에서 실패할 수 있다.
- 실사 영상을 프레임 단위로 탐색하면 키프레임 간격이 넓은 원본은 멈춘다. 넣기 전에 `-g <fps>`로 재인코딩한다(`references/footage.md`).
- 한 요소의 같은 속성을 두 애니메이션이 동시에 만지지 않는다. 위치와 움직임은 겹(래퍼)을 나눈다.

## 3. 텍스트 모션 원칙 (상세 카탈로그는 `references/text-motion.md`)

**3-1. 한국어는 어절 단위로 움직인다.** 글자 단위로 쪼개면 받침 리듬이 깨지고 읽는 속도가 떨어진다. 글자 단위 연출은 2~4자 히어로 단어 한 번에만. 줄바꿈은 `word-break: keep-all`, 마스크 칸에는 하단 여유(`paddingBottom .14em`)를 줘 받침이 잘리지 않게 한다.

**3-2. 기본 등장은 "마스크 아래에서 밀어 올리기".** 어절마다 `translateY 112% → 0`, 감속 곡선 `bezier(0.16,1,0.3,1)`, 14~16프레임, 어절 간격 3~5프레임. 페이드만으로 나타나는 글자는 싸 보인다. 퇴장은 등장보다 짧게(8~10프레임, 가속 곡선), 같은 방향으로 빠지지 않는다.

**3-3. 읽을 시간.** 한국어 화면 글자는 초당 5~6음절을 넘지 않게. 한 화면 완성 후 최소 0.45초, 2~5어절이면 어절당 0.2초를 더 붙잡는다. 자막은 한 줄 15자 안팎, 두 줄까지.

**3-4. 강조는 한 영상에 한 장치.** 색(이끼색 하나), 형광 띠, 밑줄, 상자 중 하나를 골라 영상 전체에서 그것만 쓴다. 한 줄에 장치 두 개 금지. 강조어는 영상당 3개 이하.

**3-5. 크기(1080×1920 기준).** 히어로 120~156px(세리프 900), 제목 96~118px, 보조 줄 54~60px(산세리프 500), 라벨 30~34px(자간 0.14~0.2em). 30px 미만은 "질감"이지 글자가 아니다 — 나누거나 빼고, 줄이지 않는다. 한 화면 텍스트는 2단계까지.

**3-6. 안전 영역(9:16).** 좌 96px · 우 164px(플랫폼 버튼 열) · 위 288px · 아래 480px(제목·설명 오버레이) 안에 핵심 글자를 둔다. 플랫폼별 수치는 `references/footage.md`.

**3-7. 컷 대신 이어지는 도형 하나.** 장면이 바뀌어도 끊기지 않는 물체 하나(사각 틀, 선, 점)가 크기·위치·역할을 바꾸며 이어지면 슬라이드쇼 느낌이 사라진다. `mg-shorts/src/Manifesto.tsx`의 `Frame`: 피드 사진 한 장 → 뷰파인더 → 지층 단면 → 섹션 선택 상자 → 엔드 카드 표식.

**3-8. 글자가 뜻을 연기하게.** "덜어낸다"는 지워지며 떨어지고, "사계절"은 계절이 굴러가다 내려앉고, "세 개의 층"은 아래에서부터 쌓인다. 영상당 1~2번. 모든 단어에 하면 장난이 된다.

**3-9. 첫 프레임은 썸네일이다.** 0프레임이 빈 화면이면 피드에서 스크롤을 멈추지 못한다. 첫 프레임부터 화면이 차 있어야 한다.

## 4. 실사 영상과 합칠 때 (상세는 `references/footage.md`)

- **결정은 단어로, 자르는 위치는 스크립트로.** 전사(단어 타임스탬프) → Claude가 남길 단어 범위를 고름 → 스크립트가 음성 에너지로 정확한 컷 지점을 찾아 프레임에 맞춘다. 볼륨만으로 무음을 자르면 조각이 수백 개로 잘게 난다.
- **원본 기준 EDL 하나.** 자막·그래픽·효과음 시간은 전부 EDL을 통해 원본 시간에서 환산한다. 잘린 영상을 다시 Whisper에 넣어 자막 시간을 얻지 않는다(뒤로 갈수록 1초 넘게 밀린다).
- **한국어 전사:** Whisper `.en` 모델 금지(영어로 번역해 버린다). `large-v3`, `condition_on_previous_text=False`. 무음 구간에서 단어를 지어내니 고유명사·식물명은 사람이 검수한다.
- **자막은 단어보다 2프레임 먼저 뜨고, 다음 자막 시작 직전까지 유지.** 쇼츠 1~3어절, 차분한 영상 4~6어절. 얼굴(입·턱) 위에 두지 않는다.
- **합성 경로:** 그래픽을 알파로 렌더(ProRes 4444 또는 VP9 WebM 알파) → ffmpeg `overlay`. VP9 알파를 읽을 땐 `-c:v libvpx-vp9`를 `-i` 앞에 둬야 알파가 산다. H.264에는 알파가 없다.
- **오디오:** 최종 파일에서 측정해 −14 LUFS, 트루피크 −1 dBTP 이하. 음악은 말 아래 15~21dB. 효과음은 보이는 동작에만, 컷마다 휘익 소리는 싸구려.

## 5. 박자·내레이션 맞추기 (상세는 `references/beat-sync.md`)

- 음악이 있으면 **측정한 박 목록**으로 맞춘다. BPM × 시간으로 격자를 만들지 않는다(템포가 흔들려 30마디 뒤 한 박 어긋난다). 박 시각은 하나씩 `round(t·fps)`.
- 음악이 아직 없으면 정수 프레임 BPM으로 격자를 깐다: 30fps에서 100 BPM = 18프레임/박(반박 9). `mg-shorts`는 이 격자 위에 있어 100 BPM 곡을 깔면 컷이 박에 떨어진다.
- 컷은 박 위, 레이아웃 변화는 마디 위. 박에 *착지*해야 하는 움직임은 자기 길이만큼 먼저 시작한다. 가사는 목소리보다 0.1~0.2초 먼저, 말 자막은 발화 시작에 맞춰 0.2초 더 남긴다.
- 화면 전체 번쩍임은 초당 3회 이하(광과민성).

## 6. 하지 말 것 (공개 스킬들이 공통으로 "AI가 만든 티"로 꼽은 것)

모든 단어 페이드인 · 같은 간격·같은 거리·같은 곡선 반복 · 모든 등장에 튕김 · 제목 뒤 빛번짐 · 화면 구석의 장식용 HUD(타임코드·BPM·괄호) · 슬라이드식 구성(제목 → 소제목 → 카드 3개 → 로고) · "~가 아닙니다, ~입니다" 같은 슬로건 문형 · 타자기로 치는 제목 · 장면마다 같은 전환 · 둥실거리는 무한 반복 · 1.4초 넘게 멈춘 웹 푸터식 엔드 카드.

## 7. 검증 — 눈대중이 아니라 산출물로

1. **키 프레임 스틸**: 장면마다 1~2장을 `npx remotion still`로 뽑아 보고, 겹침·잘림·대체 서체를 고친다.
2. **본 렌더 후** `python3 .claude/skills/video-motion/scripts/qa_video.py <mp4>` 실행:
   - 해상도·fps·프레임 수·`yuv420p`·tv 범위 확인(Remotion JPEG 렌더는 `yuvj420p` 전체 범위로 나온다 → 아래 변환 필수)
   - 첫 프레임 빈 화면 여부, 1.5초 간격 접촉 인화, 블랙·정지 구간, 오디오가 있으면 LUFS/트루피크
3. **접촉 인화를 직접 본다.** 프레임마다 "무엇이 보이는가"를 한 문장으로 말할 수 있어야 한다. 글자를 가려도 그림이 남는가, 휴대폰 폭(360px)에서 읽히는가.
4. **납품 인코딩:**
   ```bash
   ffmpeg -i raw.mp4 -vf "scale=in_range=full:out_range=tv,format=yuv420p" \
     -c:v libx264 -preset slow -crf 16 -profile:v high -level 4.2 \
     -color_range tv -colorspace bt709 -color_primaries bt709 -color_trc bt709 \
     -movflags +faststart out.mp4
   ```
5. 보고할 때는 **본 것과 측정만 한 것을 구분**한다(예: "소리는 들어 보지 않았다", "실사 원본은 없어 합성은 검증하지 못했다").

## 8. 새 영상 만드는 순서 (mg-shorts 기준)

1. `mg-shorts/src/`에 새 컴포지션 파일, `Root.tsx`에 등록.
2. 맨 위 주석에 서사(한 줄), 끊기지 않는 도형, 박자 격자, 안전 영역을 적는다.
3. `SCENES` 표(시작 프레임·길이, 반박 배수)를 먼저 쓰고 장면 컴포넌트를 채운다. 프리미티브는 `src/motion.tsx`(`MaskLine`, `Fade`, `prog`, `SPR`)를 쓴다.
4. 스틸 8~12장 → 수정 → 본 렌더 → 범위 변환 → `qa_video.py` → 접촉 인화 확인 → 납품.

## 9. 동화책(수채) 결 — `mg-shorts/src/Storybook.tsx`

도형·단색이 아니라 그림책처럼 보여야 할 때. 기법과 부품은 `src/story/kit.tsx`.

- **멀티플레인 카메라**: 그림을 깊이 d 층으로 나누고(하늘 14 · 먼 언덕 6 · 가까운 언덕 3 · 땅 1 · 전경 0.62), 카메라 (x, y, z)에서 각 층을 `scale = d/(d−z)`, `translate = −cam/(d−z)`로 놓는다. 밀고 들어가면 전경 꽃이 양옆으로 지나가고, 수직 이동하면 땅속 단면으로 내려간다. z는 가장 가까운 층의 d보다 작게.
- **수채**: 시드 고정 물감 덩어리(`blob`) + 가장자리 진한 물감(`Wash`) + 저주파 변위 필터(`#wc0~3`). 층 단위로 필터를 건다(도형마다 걸면 느리다).
- **선 끓음**: 필터 시드를 3프레임마다 바꿔(`boil`) 10fps로 떨리게, 카메라·빛은 30fps로 부드럽게. 손그림 대상(나비 날갯짓)은 2프레임 단위.
- **이어지는 대상**: 나비 한 마리를 Catmull-Rom 경로(`[프레임, x, y]` 키)로 모든 장면에 날린다. 같은 점이 이어지면 앉아 있고, 날갯짓은 속도로 정한다.
- **물리**: 간판 사슬은 감쇠 진동 `A·e^(−ζωt)·sin(ω_d t)`을 중첩 회전으로(위가 흔들리면 아래가 따라 돈다), 나무는 가지마다 시작 프레임을 미리 정한 재귀 성장 + 바람 흔들림 + 계절 색 보간, 꽃 개화는 ζ≈0.45 스프링(동화 결에서는 탄성 허용).
- **글**: 찢은 종이 카드 위에 어절이 흐림 7px→0으로 잉크처럼 스며든다. 어절 간격은 글자 크기에 비례한 px로(부모 em 기준이면 4px로 붙어 버린다 — 실제로 겪은 버그).
- **마무리**: 3D 책장 넘김(`rotateY` 0→−180°, 왼쪽 축, 앞면 음영·엔드 페이지에 드리우는 그림자) → 제목 획 따라 쓰기(`<text>`의 `stroke-dashoffset` 후 면 채우기).
- **종이 질감**은 `PaperTex`로 한 번 구워 `public/paper.png`(곱하기 합성). 매 프레임 노이즈를 다시 계산하지 않는다.
- 주의: 화면 밝게(screen) 합성하는 빛망울은 적게(20개 안팎, 불투명 0.2~0.45). 많으면 화면 전체가 뿌옇게 뜬다.

## 10. 아케이드(픽셀) 결 — `mg-shorts/src/Arcade.tsx` 「구근의 모험」

- **진짜 저해상도**: 180×320 논리 캔버스를 정확히 6배(`image-rendering: pixelated`). 확대도 정수·1.5배처럼 픽셀이 무너지지 않는 배율만. 픽셀 글꼴(갈무리11 · Press Start 2P, 둘 다 OFL)은 설계 크기의 배수(갈무리 12px×6=72, 한 줄 자막은 66)로.
- **하나의 타임라인**: `src/arcade/timeline.json`을 화면(TSX)과 소리(`scripts/chiptune.py`)가 같이 읽는다. 점프·타격·코인 소리가 프레임 단위로 맞는다. 박자 120 BPM = 15f/박, 장면 경계는 마디(60f) 배수.
- **8비트 소리**: 사각파(펄스 폭 12.5/25/50%) · 삼각파 베이스 · 붙잡은 노이즈 드럼만으로 생성(선율은 새로 작곡). 효과음 이름표: coin/start/hop/dig/frost/powerup/collect/burst/clear/oneup/count. 납품 때 `loudnorm=I=-14:TP=-1.5`.
- **배경은 픽셀 버퍼**(ImageData)에 4×4 베이어 디더링 그라디언트, 캐릭터는 문자열 그리드 스프라이트(캐시). 장면 전환은 같은 베이어 문턱으로 픽셀 디졸브 — 완전히 검은 프레임에서 카메라 배율을 바꾸면 이음매가 보이지 않는다.
- **손맛**: 박자 위 점프 + 착지 찌그러짐(1.2×0.82, 3f), 맞으면 흰 실루엣 3f + 화면 흔들림(논리 1px 정수) + 히트스톱, 점수는 이벤트마다 10f 롤업, 팝업(+100) 18f, INSERT COIN 2Hz 깜빡임, 대화 상자 한 글자씩 찍기.
- **브라운관**: 논리 한 줄마다 주사선(6px 주기), RGB 세로 마스크(screen 합성), 비네팅, 유리 반사, 미세 밝기 떨림, 캔버스 복제본 블러로 빛 번짐.
- **배치**: HUD는 위 288px 아래로, 게이지·자막은 고정 줄(자막 상자 위)에 DOM으로. 캔버스 안 게이지는 확대 때 자막과 겹쳤다 — 화면 고정 요소는 DOM으로 빼는 게 맞다.
- **캐릭터·음악은 전부 새로 만든다.** 특정 게임의 캐릭터·레벨·음악·이름을 따라 하지 않는다(장르 문법만 빌린다).
