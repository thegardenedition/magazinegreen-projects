# GREEN GRADE

사진을 올리면 영상 컬러그레이딩 방식(컬러 휠, 노드, 스코프)으로 보정하고 내보내는 웹앱입니다.
정원·조경 사진을 다루는 매거진 에디터를 위해 만들었습니다.
서버 없이 브라우저 안에서만 동작하며, 사진은 외부로 전송되지 않습니다.

> 현재 단계: **Phase 5 완료** (기획한 다섯 단계 모두)
> - Phase 1 — 업로드, WebGL 파이프라인, Before/After 뷰어, Primary 휠, JPG 내보내기
> - Phase 2 — Curves(Custom Y/R/G/B, Hue vs Hue/Sat/Lum, Lum vs Sat), 스코프 4종, 되돌리기/다시 실행
> - Phase 3 — 노드 체인(Serial, 최대 8개), .cube 3D LUT, 프리셋 저장·불러오기, 정원 프리셋 5종 (이후 기본 프리셋 135종 · LUT 라이브러리 145종으로 확장)
> - Phase 4 — HSL Qualifier(스포이드), Window(원형·사각형·그라디언트·펜), 마스크 보기
> - Phase 5 — 여러 장 작업(그레이드 복사·붙여넣기, ZIP 일괄 내보내기), 그레이드 → .cube 내보내기, 정원 프리셋 수치 검증·재조정
> - 추가 — 형태(90° 회전·반전, 수평·기준선, 원근, 비율 크롭), 디테일(샤프닝, 노이즈 감소, 텍스처, 선명도, 디헤이즈, 그레인), 긴 변 크기로 내보내기

## 실행

```bash
cd green-grade
npm install
npm run dev        # http://localhost:5173
npm run build      # 타입체크 + dist/ 정적 빌드 (어느 정적 호스팅에나 올릴 수 있음)
npm test           # 단위 테스트 (기준 수식)
npm run test:e2e   # Playwright E2E (빌드 후 미리보기 서버에서 실행)
```

WebGL2를 지원하는 최신 Chrome, Edge, Safari, Firefox가 필요합니다.

## 색처리 파이프라인

```
 파일 (JPG/PNG/WebP)
   │  createImageBitmap — EXIF 회전 반영, 내장 ICC 프로파일 → sRGB 변환
   ▼
 sRGB 8bit 텍스처 ──────────────── 미리보기: 긴 변 3072px 프록시 + 밉맵
   │                                내보내기: 원본 해상도, 2048px 타일 단위
   ▼  (여기서부터 셰이더 안에서 fp32로 연산)
 ① sRGB → 선형(Linear)
   ┌─ 노드 01 → 노드 02 → … (켜진 노드만, 최대 8개, 아래 ②–⑭를 노드마다 반복) ─┐
 ② 화이트밸런스  Temp / Tint      선형 · 채널 곱 (중립 회색 휘도 유지)
 ③ Offset                         선형 · 2^EV 곱 (노출)
 ④ Gain                           선형 · 채널 곱
 ⑤ 그레이딩 인코딩  p = x^(1/2.4)
 ⑥ Lift            p + lift·(1−p)       흰색 고정, 검정을 들어 올림
 ⑦ Gamma           p^(1/(1+g))          검정·흰색 고정, 중간톤 이동
 ⑧ Contrast/Pivot  (p−pivot)·c + pivot  기본 pivot 0.489 = 18% 그레이
 ⑧' 구간 조정       Shadows·Highlights 막대 + Log 휠(Shadow·Midtone·Highlight, Low/High Range)
 ⑨ Custom Curves   Y(전 채널) → R/G/B     단조 3차 보간 표, 0–1 밖은 평행 이동
 ⑩ 선형 복귀       x = p^2.4
 ⑪ Saturation      Rec.709 휘도 기준, 이어서 Color Boost(탁한 색일수록 더)
 ⑫ Hue · RGB Mixer 회색 축 회전과 채널 혼합을 한 행렬로 (Mixer 먼저)
 ⑬ 색상 커브        그레이딩 인코딩의 Y'CbCr에서
                    Hue vs Hue (색상각 ±60°) · Hue vs Sat (×0–2)
                    Hue vs Lum (루마 ±50%, 무채색 제외) · Lum vs Sat (×0–2)
                    Sat vs Sat (×0–2) · Sat vs Lum (±50%) — 가로축 채도
 ⑭ LUT             선형 → sRGB 코드값 → 3D LUT(3선형 보간) → 선형, 강도만큼 섞음
   ⊕ 마스크         노드 출력 = mix(노드 입력, ②–⑭ 결과, Qualifier × Window)
   └──────────────────────────────────────────────────────────────────────┘
 ⑮ 선형 → sRGB, 1 LSB 삼각 분포 디더(픽셀 좌표 기반) → 8bit
   ▼
 화면 / JPG
```

**왜 두 공간을 나누는가.** 노출, 화이트밸런스, Gain처럼 빛의 양을 곱하는 조작은 선형 공간에서 해야
물리적으로 맞습니다. 반면 Lift, Gamma, Contrast는 사람이 느끼는 밝기 단계를 다루므로 선형 공간에서
적용하면 섀도가 과하게 뭉개집니다. 그래서 톤 조작만 지각적 인코딩(감마 2.4)으로 옮겨 처리하고
다시 선형으로 돌아옵니다.

**컬러 휠.** 휠 위치는 벡터스코프의 U(가로)·V(세로) 축과 같은 방향이며, 휠의 색 편차는 휘도가 정확히
0이 되도록 계산합니다. 휠은 색만, 아래 다이얼은 밝기만 바꿉니다.

**커브.** 모든 커브는 1024칸 표(RGBA32F 텍스처 1024×3)로 구워 셰이더가 읽고, CPU 기준 구현도 같은 표와
같은 선형 보간을 씁니다. 보간은 단조 3차(Fritsch–Carlson)라 점 사이에서 값이 튀어 오르지 않아 계조 반전이나
의도하지 않은 클리핑이 생기지 않습니다. 색상축은 빨강(0)에서 시작해 노랑 → 초록 → 청록 → 파랑 → 마젠타 순이며,
0과 1이 이어진 주기 커브입니다. 색상 커브에 점을 찍으면 양옆(±0.08)에 고정점이 함께 생겨 고른 색 주변만 바뀝니다.

**결정성.** 같은 입력과 같은 보정값은 항상 같은 출력을 냅니다. 디더 노이즈도 픽셀 좌표로 정해지므로
타일 분할 방식과 무관합니다.

기준 수식은 `src/engine/color.ts`·`src/engine/curves.ts`, GLSL은 `src/engine/shaders.ts`에 있으며 둘은 1:1로 대응합니다.

**노드 체인은 한 번의 셰이더 패스.** 노드마다 렌더 패스를 따로 돌리고 중간 결과를 반정밀도(16bit float)
버퍼에 담는 방식 대신, 노드별 값을 길이 8의 배열로 넘겨 셰이더 안에서 노드를 차례로 통과시킵니다. 노드 사이 값이
fp32로 유지되어 밴딩이 생기지 않고, 미리보기·타일 내보내기·스코프가 같은 코드 경로를 씁니다. 대신 노드는 최대 8개입니다.

**LUT.** 노드 보정이 끝난 뒤에 적용합니다. 입력은 sRGB 코드값(0–1, DOMAIN_MIN/MAX를 따름)이며, 3선형 보간은
하드웨어 필터링 대신 셰이더에서 직접 계산해 CPU 기준 구현과 같은 값을 냅니다. LUT 데이터는 RGBA32F 3D 텍스처로
노드 칸마다 하나씩 올라갑니다. 최대 크기는 65³입니다.

## 형태 · 디테일 (사진 전체)

노드 보정 앞에서 사진마다 한 번 처리합니다. `형태`·`디테일` 탭은 선택 노드가 아니라 사진 전체에 적용되며(탭 오른쪽에
'사진 전체'로 표시), 되돌리기와 사진별 기억, 일괄 내보내기에 모두 포함됩니다.

```
 원본 8bit ─▶ ① 형태 변환 ─▶ ② 노이즈 감소 ─▶ ③ 휘도 블러 2종 ─▶ ④ 합성 ─▶ 노드 01 → … ─▶ ⑤ 그레인 ─▶ 디더 → 8bit
              90° 회전·반전      휘도: 양방향 필터    샤프닝용(작은 σ)       샤프닝·텍스처·선명도
              원근(사영 변환)    색상: 밝기 경계를     텍스처용(중간 σ)       디헤이즈(다크 채널)
              수평 → 크롭        지키는 크로마 블러
```

- **형태 탭**
  - 90° 회전, 좌우·상하 반전
  - 수평 −45–45°: 기울이면 빈 모서리가 생기지 않는 가장 큰 크롭으로 자동으로 줄어듭니다.
  - **기준선 긋기**: 뷰어에서 지평선·처마선·기둥을 따라 끌면 그 선이 수평(또는 수직)이 되도록 돌립니다.
  - 세로·가로 원근: 사영 변환이라 직선이 직선으로 남습니다. 세로 +는 올려다 찍어 위로 모이는 기둥과 건물을 폅니다.
  - 크롭: 비율은 자유·원본·1:1·4:5·5:4·3:2·2:3·16:9·9:16입니다. 뷰어의 사각형을 끌어 옮기고, 모서리를 끌어 크기를 바꿉니다.
    3분할 격자가 함께 보이며, 원본 밖이 들어오는 위치로는 끌리지 않습니다.
  - 형태 탭에서는 크롭 전 전체 프레임과 크롭 사각형이 보이고, 다른 탭으로 가면 크롭 결과만 보입니다.
- **디테일 탭**
  - **샤프닝**: 양·반경(원본 픽셀 기준)·마스킹. 휘도에만 걸어 색 테두리가 생기지 않으며, 마스킹을 올리면 하늘 같은 평평한 곳의 잡티는 덜 날카로워집니다.
  - **노이즈 감소**
    - 휘도: 밝기 차가 큰 경계는 지키는 양방향 필터
    - 색상: 밝기 경계를 넘지 않는 크로마 블러
  - **질감**
    - 텍스처: 잎·잔디 같은 중간 크기 굴곡
    - 선명도: 긴 변의 약 1.2% 크기의 국소 대비, 중간톤 위주
    - 디헤이즈: 다크 채널로 안개 정도와 대기광을 추정해 걷어 냅니다. −로 하면 안개를 더합니다.
  - **그레인**: 원본 해상도 기준 크기(긴 변 2000칸 × 크기)의 단색 노이즈. 출력 좌표에 묶여 있어 미리보기와 내보내기의 무늬가 같습니다. 노드 보정 뒤에 더합니다.
- **내보내기 크기**: 내보내기 창과 일괄 내보내기에서 긴 변을 원본·4096·3000·2048·1600·1080px 중에서 고릅니다. 크롭한 결과를 줄입니다.
- **복사·붙여넣기**: 그레이드를 복사하면 디테일도 함께 옮겨지고, 형태(회전·크롭)는 사진마다 달라 옮기지 않습니다.

구현 메모
- 형태는 출력 좌표 → 원본 좌표 3×3 사영 행렬 하나로 처리합니다(`src/engine/develop.ts` `geometryMatrix`).
  원근·회전은 프레임 높이를 1로 둔 좌표에서 계산하므로 미리보기·썸네일·원본이 같은 결과를 냅니다.
- 디테일은 실수 렌더 타깃(`EXT_color_buffer_float`)을 쓰는 4개 패스입니다(`src/engine/developGL.ts`).
  - 원본은 1024px 타일로 나누고, 타일마다 블러·노이즈 반경만큼 가장자리를 더 계산합니다.
  - 이웃 픽셀은 항상 출력 이미지 좌표를 가장자리에 고정한 뒤 읽으므로 타일 경계에서 결과가 끊기지 않습니다.
- 선명도·디헤이즈의 기준은 원본을 긴 변 512px로 줄인 사본에서 긴 변 320칸 격자로 만듭니다.
  - 미리보기·내보내기가 같은 기준을 쓰므로 큰 흐름이 같습니다.
  - 픽셀마다 쌍선형 보간합니다.
- CPU 기준 구현(`developReference`)이 같은 수식을 따르며, E2E에서 GPU 결과와 1 LSB 이내로 맞는지 확인합니다.

## 프로 워크플로: 로그로 평탄화한 뒤 색 입히기

영상 컬러리스트와 사진 리터처가 쓰는 방식입니다.
1. 원본의 대비·채도를 먼저 빼서 카메라 로그(D-Log, S-Log3, LogC3 등)처럼 평탄한 상태로 만듭니다.
2. 그 위에서 노출·색을 고르게 맞춥니다.
3. 로그 입력용 룩 LUT로 색감을 입힙니다.

- **로그로 변환 LUT 19종** (LUT 탭 '로그로 변환')
  - 'sRGB → DJI D-Log / D-Gamut'처럼 사진을 카메라 로그·색역으로 바꿉니다.
  - 카메라 로그 LUT('로그 → sRGB')의 정확한 역변환입니다. 왕복하면 원본과 2 LSB 이내(65³ 기준)로 돌아옵니다.
  - 그래서 그 로그용으로 만든 상용 LUT를 사진에 그대로 쓸 수 있습니다.
  - 표시 기준 사진의 흰색(선형 1.0)은 18% 회색 기준으로 약 +2.5 스톱이라, 로그 상태에서는 회색빛으로 평탄하게 보입니다.
- **프로 룩 LUT 16종** (LUT 탭 '프로 룩', ARRI LogC3 입력 → sRGB)
  - 장면 선형에서 노출·화이트밸런스·채널 간섭·채도·색상별 미세 조정(피부·잎·하늘)을 하고, 채널마다 필름 곡선을 씌웁니다.
  - 필름 곡선은 18% 회색을 그대로 두고 하이라이트를 부드럽게 1로 수렴시킵니다. 흰색은 잘리지 않고 약 230–249에 머뭅니다.
  - 표시 공간에서 하이라이트 채도 억제, 스플릿 톤, 블랙 레벨을 더합니다.
  - 목록:
    - 시네마 표준, 인물 네거티브, 풍경 네거티브, 다큐 크롬
    - 리버설 슬라이드, 텅스텐 나이트, 블리치 시네마, 틸 & 오렌지 프로
    - 웨딩 에어리, 드라마 소프트, 매거진 에디토리얼, 무디 포레스트
    - 가든 골든, 노르딕 매트, 빈티지 프린트, 실버 흑백
  - 특정 필름이나 회사 LUT를 측정한 것이 아니라, 특성을 따라 만든 스타일입니다.
- **프로 워크플로 프리셋 23종** (Presets 탭 '프로 워크플로')
  - '프로 · ○○' 16종
    - 노드: '로그 변환'(sRGB → LogC3) → '1차 보정 (Log)'(빈 노드) → 룩 LUT.
    - 로그 상태에서는 Offset이 노출처럼, 휠이 넓은 계조에 고르게 움직입니다.
    - 질감(그레인·할레이션·글로우·비네트·선명도)은 디테일 효과로 함께 겁니다. LUT는 색만 바꿀 수 있어 질감은 효과로 냅니다.
  - '로그 베이스 · ○○' 7종: D-Log, S-Log3, LogC3, V-Log, F-Log2, Canon Log 3, Apple Log
    - 노드: 로그 변환 → 1차 보정 → '룩 LUT (바꿔 쓰기)'.
    - 마지막 노드에는 그 카메라의 '로그 → sRGB'가 들어 있습니다.
    - LUT 탭에서 '바꾸기'로 갖고 있는 상용 LUT를 넣으면 그 색감이 입혀집니다.
- **일괄 적용**: 필름스트립에서 사진을 체크하고 Presets 탭의 '선택한 사진에도 적용'을 켜면, 누른 프리셋이 지금 사진과 고른 사진 모두에 한 번에 들어갑니다(효과 포함).
- 프리셋은 LUT를 데이터로 들고 있지 않고 이름(`lutRef`)으로 가리키다가, 적용할 때 만듭니다.

## DaVinci Resolve에서 가져온 보정 도구

Resolve 컬러 페이지에 있고 이 앱에 없던 도구 중, 노드 보정 구조(한 번의 셰이더 패스)에 들어가는 것을 넣었습니다.
모두 CPU 기준 구현과 같은 수식이며, E2E에서 GPU 결과가 1 LSB 이내로 맞는지 확인합니다.

| Resolve | 이 앱 | 위치 |
|---|---|---|
| Primaries 막대: Shadows · Highlights · Color Boost | 같은 이름 슬라이더 (−100–100) | Primary 탭 |
| Log 휠 (Shadow·Midtone·Highlight, Low/High Range) | 'Log 휠'로 바꿔 보기. Primary 휠과 함께 적용 | Primary 탭 |
| RGB Mixer (Monochrome, Preserve Luminance) | 출력 R·G·B마다 입력 비율, 흑백, 휘도 유지 | RGB Mixer 탭 |
| Curves: Sat vs Sat · Sat vs Lum | 가로축이 채도(Qualifier와 같은 축)인 커브 2종 | Curves 탭 |
| Film Look·FX: Vignette · Glow · Halation | 비네트(양·중심·부드러움), 글로우, 할레이션 | 디테일 탭 '효과' |
| LUT: .cube · .3dl, LUT 폴더 | .3dl 읽기, 여러 파일 한 번에, 끌어다 놓기, '내 LUT' 보관 | LUT 탭 |

- **Shadows / Highlights**: 그레이딩 인코딩 휘도의 어두운 쪽·밝은 쪽에만 밝기를 더하고 뺍니다. 그늘을 들거나 하늘을 살릴 때.
- **Color Boost**: 채도가 낮은 색일수록 채도를 더 올리고(−면 내리고), 이미 진한 색과 회색은 거의 그대로 둡니다.
- **Log 휠**
  - Low Range 아래는 Shadow 휠, High Range 위는 Highlight 휠, 사이는 Midtone 휠이 색·밝기를 더합니다(경계는 부드럽게 겹침).
  - Primary 휠이 전체 계조를 늘이고 당긴다면, Log 휠은 구간을 나눠 미는 도구입니다.
- **RGB Mixer**: 선형 RGB에서 섞습니다.
  - 흑백을 켜면 '출력 R' 행 하나로 흑백을 만듭니다. 예: 입력 G를 높이면 잎이 밝은 녹색 필터 흑백.
  - 휘도 유지는 행마다 합이 1이 되도록 맞춥니다.
- **Sat vs Sat / Sat vs Lum**: 이미 진한 꽃색만 채도를 낮추거나 어둡게 하는 식으로, 채도에 따라 다르게 조정합니다.
- **비네트·글로우·할레이션** (디테일 탭 '효과', 사진 전체, 노드 보정 앞)
  - 비네트: 크롭 결과 기준으로 모서리를 어둡게(+) 또는 밝게(−).
  - 글로우: 밝은 부분(선형 0.55 이상)을 긴 변의 약 3% 반경으로 번지게 더합니다.
  - 할레이션: 밝은 부분 휘도를 긴 변의 약 0.8% 반경으로 번지게 해 붉은 주황빛으로 더합니다. 필름 뒷면 반사를 흉내 냅니다.
  - 글로우와 할레이션은 선명도·디헤이즈와 같은 저해상도 기준 격자에서 계산해, 미리보기와 내보내기가 같은 모양을 냅니다.
- **LUT 삽입**
  - LUT 탭 'LUT 파일 불러오기'에서 .cube·.3dl을 여러 개 고르거나, 화면 어디에든 끌어다 놓습니다.
  - 첫 파일은 선택 노드에 바로 적용되고, 모두 '내 LUT'에 보관됩니다.
  - 보관은 이 브라우저의 IndexedDB이므로 새로고침해도 남고, 다른 브라우저·기기에는 없습니다. ×로 지웁니다.
  - .3dl은 첫 줄 입력 격자, 'Mesh' 줄의 출력 비트 수(없으면 값 범위로 10·12·16bit 추정), 파랑이 가장 빨리 바뀌는 순서를 따릅니다.

넣지 않은 것: 노드별 블러·샤프닝, Color Warper, HDR 존 휠, Parallel·Layer 노드, 트래킹.
노드 보정을 한 번의 셰이더 패스로 처리하는 구조라, 주변 픽셀을 보거나 노드를 갈래로 나누는 도구는 들어가지 않습니다.

## 마스크 (Qualifier · Window)

**마스크가 켜진 노드 알아보기.**
- 노드 카드에 표시가 붙습니다: 창이 켜졌으면 '창 안'·'창 바깥', Qualifier가 켜졌으면 '고른 색만'·'고른 색 제외'.
- 그런 노드를 Primary·Curves 탭에서 보정하면 위에 '이 노드의 보정은 ○○에만 적용됩니다' 안내가 뜹니다.
  - '창 끄기'·'Qualifier 끄기'로 바로 사진 전체에 걸리게 할 수 있습니다.
  - '전체용 새 노드'로 마스크 없는 노드를 하나 더 만들 수 있습니다.
- 예: '비네트'·'무디 다크'·'로우키' 프리셋의 '비네트' 노드는 창 바깥(가장자리)에만 적용됩니다.

노드마다 Qualifier 하나와 Window 하나를 둘 수 있고, 노드의 보정은 마스크 값만큼만 들어갑니다.
둘 다 켜면 곱(교집합), 각각 반전할 수 있습니다.

**HSL Qualifier** — 색으로 고르기
- 판정 기준은 **이 노드에 들어오는 색**(앞 노드를 거친 색)이며, 색상 커브와 같은 Y'CbCr(감마 2.4) 공간을 씁니다.
  색상축(빨강 0 → 노랑 → 초록 → 청록 → 파랑 → 마젠타)도 Hue 커브와 같습니다.
- Hue: 중심·폭·소프트 (색상축이 한 바퀴 이어져 빨강 양쪽도 고를 수 있음). 무채색은 색상이 없으므로 Hue 선택에서 빠집니다.
- Sat: 크로마 0.5를 채도 1로 본 낮음·높음·소프트. Lum: 루마 낮음·높음·소프트. 0과 1 끝은 경계로 보지 않습니다.
- **스포이드**: 뷰어를 누르면 주변 5×5 픽셀(미리보기 해상도)을 앞 노드까지 처리한 색으로 범위를 새로 정합니다.
  **+ 더하기**는 기존 범위를 넓혀 새 색까지 포함합니다.

**Window** — 영역으로 고르기
- 원형·사각형: 중심·크기·회전, 페더. 뷰어에서 중심/가로/세로/회전 핸들을 끌어 고칩니다.
- 그라디언트: 시작점에서 1, 끝점에서 0. 기본값은 하늘용(위쪽 → 화면 중간).
- 펜: 뷰어를 눌러 꼭짓점을 찍고(3개부터 적용), 점을 끌어 옮기고 더블클릭으로 지웁니다.
  '부드러운 곡선'을 켜면 꼭짓점을 지나는 Catmull-Rom 곡선으로 이어집니다(최대 64점으로 펼침).
- 좌표는 이미지 기준 0–1, 크기와 페더는 이미지 높이 기준이라 원은 사진 비율과 상관없이 원입니다.

**마스크 보기**(`Shift+H`): 선택 노드의 마스크를 하이라이트(선택 밖을 어둡고 흐리게) 또는 흑백으로 봅니다.

## LUT 라이브러리

LUT 탭의 'LUT 라이브러리'(분류 칩과 검색)에서 누르면 선택 노드에 들어갑니다(대부분 33³, 가파른 1차원 곡선은 65³).
파일로 들고 있지 않고 쓸 때 수식으로 계산합니다(`src/engine/lutLibrary.ts`). 구성은 DaVinci Resolve에 딸린 LUT 폴더
(카메라 제조사별, VFX IO, Film Looks)를 따랐지만, 그 파일을 옮긴 것이 아니라 공개된 수식으로 직접 만든 것입니다.

**카메라 로그 LUT.** 제조사가 공개한 로그 곡선과 색역 원색 좌표로 계산합니다.
- 계산: 로그 코드값 → 장면 선형 → 카메라 색역에서 Rec.709/sRGB 원색으로(D65 → D65) → sRGB.
- 입력은 파일에 저장된 코드값(0–1) 그대로입니다. Canon Log·Log 2·Log 3과 S-Log2는 제조사 수식대로 비디오 레벨 코드값을 받습니다.
- '부드러운 하이라이트'는 선형 0.55 위를 기울기가 이어지게 눌러 1에 다가가게 합니다.
- 모든 카메라에서 18% 회색 코드값이 무채색 sRGB 118±3이 되는지 테스트합니다.

**Sony 스타일 3종**(S-Log3 / S-Gamut3.Cine 입력): LC-709 스타일(낮은 대비, 들린 블랙) · LC-709 Type A 스타일(조금 진한 색) ·
Cine+709 스타일(단단한 대비). Sony가 배포하는 같은 이름 LUT의 데이터가 공개돼 있지 않아 특성을 따라 만든 근사입니다.

**필름 룩**은 Rec.709/sRGB 입력에 프린트 필름의 특성을 씌웁니다.
- 염료 간섭(채널 혼합), 채널별 S커브, 청록 섀도·따뜻한 하이라이트, 하이라이트 채도 억제, 흰색 D55·D60·D65.
- 2383 스타일은 깊은 블랙과 단단한 대비, 3513DI 스타일은 조금 낮은 대비와 차분한 녹색입니다.
- 필름 제조사나 Blackmagic의 측정 LUT가 아니라 스타일 근사입니다.

**.cube로 받기.** LUT 탭의 '라이브러리 145종 .cube 받기 (ZIP)'는 전체를 분류별 폴더의 .cube 파일로 묶어 내려받습니다
(압축 ZIP, 약 18MB). VFX IO는 1D LUT(4096칸), 나머지는 3D LUT(33³)입니다. 1D .cube는 이 앱에서도 불러올 수 있으며, 불러오면 65³ 3D LUT로 바뀝니다.
DaVinci Resolve에서는 Project Settings → Color Management → Lookup Tables → Open LUT Folder에 폴더째 넣고
Update Lists를 누르면 됩니다. 카메라·필름·룩 LUT의 출력은 sRGB 기준이므로, Rec.709 감마 2.4 타임라인에서 영상용으로
쓸 때는 뒤 노드에 'VFX IO/sRGB to Gamma 2.4'를 이어 두세요.

**DaVinci에 있지만 넣지 못한 것.**
- Blackmagic Gen 4 이하 필름 곡선: 공개 수식이 없습니다.
- ACES 변환: Resolve는 LUT가 아니라 색 관리로 처리합니다.
- 제조사가 만든 크리에이티브 LUT(ARRI K1S1 등): 데이터가 공개돼 있지 않습니다.

**노드 체인에서의 위치.** 카메라 로그 LUT는 첫 노드에(로그를 sRGB로 바꾼 뒤에 다른 보정을 얹도록),
룩 LUT는 마지막 노드에 두는 것이 일반적입니다.

## 정원 프리셋 검증

실제 정원에서 자주 나오는 색 30가지를 견본으로 두고(`src/engine/gardenSwatches.ts` — 잎 7종, 하늘 4종, 흙·돌·나무·벽돌,
꽃 5종, 피부 2종, 단풍 3종, 무채색), 프리셋마다 약속한 효과와 지켜야 할 선을 수치로 정해 테스트합니다
(`tests/unit/gardenPresets.test.ts`, 41개 항목). 회색 계단 반전·새 클리핑·피부 색상 같은 공통 안전선은
기본 프리셋 135종 전체에 적용되며, 분류별로 이름대로의 효과를 내는지는 `tests/unit/presetLibrary.test.ts`가 확인합니다
(예: 녹색 필터 흑백은 잎을 기본 흑백보다 5% 이상 밝게, 노출 +½은 18% 회색의 빛을 ×1.41).
화이트밸런스 보정(따뜻하게·차갑게·그늘·녹색 반사광)과 의도적으로 색을 바꾸는 룩(크로스 프로세스, 틸 & 오렌지 등)은
피부 기준을 완화하거나 제외합니다. 피부까지 함께 옮기는 것이 목적이기 때문입니다.

Phase 3의 첫 버전은 이 기준으로 재 보니 41개 중 16개를 통과하지 못했습니다. 신록은 녹색 채도가 오히려
7–12% 올랐고, 흐린 날 구제는 붉은 꽃의 G 채널을 0으로 잘랐습니다. 가장 큰 원인은 색상 위치였습니다.
실제 잎은 순수 초록(0.35)이 아니라 노랑 쪽인 0.24–0.34에, 맑은 하늘은 파랑(0.70)이 아니라 0.61에 있습니다.
지금 값은 견본에서 잰 위치에 Hue 커브 점을 다시 놓고 맞춘 것입니다.

> 견본은 대표 색일 뿐 실제 사진이 아닙니다. 빛, 렌즈, 카메라 프로파일에 따라 실제 잎과 하늘의 위치는 조금씩
> 다르므로, 실제 정원 사진으로 확인하고 필요하면 기준과 값을 함께 고쳐 주세요.

## 여러 장 작업

- **열기**: 여러 장을 한 번에 열거나 끌어다 놓으면 아래 필름스트립에 쌓입니다. 원본은 파일로만 들고 있고
  지금 여는 사진 한 장만 디코딩하므로, 수십 장을 올려도 메모리가 크게 늘지 않습니다.
- **사진마다 그레이드**: 썸네일을 누르면 그 사진으로 넘어가며, 각 사진은 자기 노드 체인을 기억합니다.
  썸네일에는 보정이 반영됩니다.
- **그레이드 복사·붙여넣기**: 지금 사진의 그레이드를 복사(`Ctrl/⌘+C`)하고, 체크박스·`Ctrl/⌘+클릭`·`Shift+클릭`으로
  고른 사진들에 붙여 넣습니다(`Ctrl/⌘+V`). 창 좌표는 이미지 비율 기준이라 크기가 다른 사진에도 같은 자리에 들어갑니다.
- **일괄 내보내기**: 고른 사진들을 각자의 그레이드·형태·디테일로 JPG를 만들어 ZIP 하나로 내려받습니다(긴 변 크기 선택 가능).
  이름은 `원래이름_GG.jpg`이고, 같은 이름은 `(2)`처럼 번호가 붙습니다.

## 그레이드 → .cube LUT

LUT 탭의 '그레이드를 LUT로 내보내기'는 켜진 노드 전체를 17³·33³·65³ 중 하나의 .cube로 굽습니다. 격자점마다 CPU 기준
구현으로 계산하므로 화면과 같은 수식이며, 33³로 다시 적용했을 때 원래 그레이드와 평균 1 LSB 이하, 최대 3–4 LSB
차이입니다. Qualifier는 색으로 정해지므로 LUT에 그대로 들어갑니다. 창(Window)은 위치 정보라 담을 수 없어,
창이 켜진 노드는 '빼고 굽기'(기본) 또는 '창을 무시하고 화면 전체에 적용' 중에서 고릅니다.

## 스코프

```
 프록시 ─▶ 분석 렌더 (가로 512px, 보정 적용, 디더 없음) ─┬─▶ 점 산포 + 가산 합성 (GPU)
                                                     │     Waveform  : x = 이미지 가로, y = 루마
                                                     │     Parade    : R·G·B 3분할
                                                     │     Vector    : Cb(가로)·Cr(세로)
                                                     │     → 반정밀도 누적 버퍼 → 로그 톤으로 표시
                                                     └─▶ 픽셀 읽기 → Histogram·클리핑 비율 (정확한 개수)
```

- 스코프는 뷰어와 별도의 WebGL2 컨텍스트에서 돌아가며, 보정값이 바뀔 때마다 다시 계산합니다.
- 측정 대상은 **출력 sRGB 코드값**입니다. 0–100 IRE는 0–255에 대응합니다.
- 벡터스코프의 방향은 컬러 휠과 같습니다(빨강 왼쪽 위, 파랑 오른쪽). 75% 컬러바 목표점과 스킨톤 라인(점선)을 표시합니다.
- 하단 표시줄: 한 채널이라도 255에 닿은 픽셀(하이라이트)과 0에 닿은 픽셀(섀도)의 비율. 0.1%를 넘으면 붉게 경고합니다.

## 되돌리기

노드 체인 전체(노드 추가·삭제·순서·이름, Primary, Curves, LUT, 노드 on/off, 프리셋 적용)가 기록 대상입니다. 드래그나 연속 입력은 손을 멈춘 뒤 0.25초가 지나면 한 단계로
묶여 기록되며, 최대 200단계까지 보관합니다.

## 휴대폰

폭 760px 이하, 또는 가로로 든 터치 화면(높이 500px 이하)에서는 휴대폰 화면으로 바뀝니다.

- **구성**
  - 위: 열기·되돌리기·분할·원본·내보내기
  - 가운데: 뷰어(고정)
  - 아래: 도구 한 가지 + 탭 막대(조정·노드·프리셋·스코프·사진)
- **가로로 들면** 뷰어가 왼쪽, 도구가 오른쪽으로 갑니다.
- **뷰어 조작**
  - 한 손가락: 이동
  - 두 손가락: 벌리고 오므려 확대·축소
  - 두 번 탭: 화면 맞춤 ↔ 3배 확대
  - 뷰어 크기가 바뀌면(회전, 형태 탭 전환) 맞춤 상태일 때 다시 맞춥니다.
- **두 번 탭 = 더블클릭**: 슬라이더·휠 리셋, 커브 점 삭제, 노드 이름 바꾸기 등 데스크톱에서 더블클릭인 동작을 두 번 탭으로 씁니다.
- **크기와 입력**
  - 손가락 크기에 맞게 버튼·슬라이더·핸들을 키웠습니다.
  - 숫자 칸은 16px 글자라 iOS가 입력할 때 화면을 확대하지 않습니다.
  - 내보내기 창은 아래에서 올라오는 시트입니다.
- **안전 영역**: 노치·홈 막대 영역(safe-area)을 비웁니다.
- **패널 유지**: 패널은 모두 만들어 두고 보이는 것만 바꾸므로, 탭을 오가도 스코프의 GPU 컨텍스트를 다시 만들지 않습니다.

## 현재 한계

- 카메라 로그 LUT는 공개 수식으로 계산했고 18% 회색과 구간 연속성을 테스트했지만, 실제 카메라 로그 영상으로는 확인하지 못했습니다. 비디오 레벨/데이터 레벨 해석은 프로그램마다 달라, 결과가 뿌옇거나 과하게 진하면 유틸리티의 '비디오 레벨 → 풀 레벨'을 앞 노드에 두세요.

- 100% 이상으로 확대하면 프록시(긴 변 3072px)가 보이므로 원본보다 덜 선명합니다. 내보내기는 항상 원본 해상도(긴 변 제한을 고르면 그 크기)입니다.
- 샤프닝·노이즈 감소 반경은 원본 픽셀 기준이라, 원본이 3072px보다 크면 미리보기에서는 실제보다 약하게 보입니다. 최종 판단은 내보낸 JPG로 하세요.
- 긴 변을 줄여 내보낼 때 샤프닝은 줄이기 전 원본에 걸립니다. 줄인 뒤 다시 거는 출력 샤프닝은 없습니다.
- 자동 수평(지평선 자동 인식)과 렌즈 왜곡·주변부 감광 보정(렌즈 프로파일)은 없습니다. 수평은 값 입력이나 기준선 긋기로 맞춥니다.
- 노이즈 감소는 양방향 필터 수준이라, 고감도 사진의 강한 노이즈에는 전용 AI 노이즈 제거만큼 깨끗하지 않습니다.
- 형태·디테일은 실수 렌더 타깃(`EXT_color_buffer_float`)이 필요합니다. 최근의 데스크톱·모바일 브라우저는 대부분 지원하며, 없으면 형태·디테일을 켤 때 오류를 알립니다.
- 스포이드는 형태(회전·크롭)는 반영하지만 디테일(샤프닝 등)은 반영하지 않은 색을 읽습니다.
- 창(Window) 위치는 크롭 결과 기준 좌표입니다. 창을 그린 뒤 크롭을 바꾸면 창이 사진 내용에서 어긋나므로, 크롭을 먼저 정하세요.
- JPG에 ICC 프로파일을 넣지 않습니다. 출력은 sRGB 기준이며, 대부분의 웹·인쇄 입고 환경에서 sRGB로 해석됩니다.
- GPU 최대 텍스처 크기(대개 8192 또는 16384px)를 넘는 사진은 아직 내보낼 수 없습니다.
- 노드는 Serial 8개까지입니다. Parallel·Layer Mixer 노드는 없습니다.
- LUT는 sRGB 사진 기준으로 만든 것을 전제로 합니다. 로그(Log) 영상용 LUT를 넣으면 색이 크게 틀어집니다.
- 내 프리셋은 브라우저 저장소(localStorage)에 있어 브라우저를 바꾸거나 사이트 데이터를 지우면 사라집니다. 오래 보관할 프리셋은 JSON으로 내보내세요.
- 정원 프리셋은 대표 색 견본으로 수치 검증했지만, 실제 정원 사진으로는 아직 확인하지 못했습니다(작업 환경에서 외부 사진을 받을 수 없었음).
- 스코프는 가로 512px 분석본으로 계산합니다. 머리카락처럼 아주 작은 영역의 클리핑은 비율에 덜 잡힐 수 있습니다.
- 스코프 갱신마다 GPU에서 분석 픽셀을 한 번 읽어옵니다(약 17만 픽셀). 히스토그램을 정확한 개수로 세기 위한 선택이며, 일반적인 노트북에서 슬라이더 조작에 지장이 없는 수준입니다.
- 커브 점을 숫자로 직접 입력하는 기능, 뷰어에서 색을 찍어 색상 커브에 점을 만드는 기능은 아직 없습니다.
- 노드당 창은 하나입니다. 여러 창을 겹치려면 노드를 나눠 쓰세요.
- 마스크 다듬기(블러, 클린 블랙/화이트)와 트래킹은 없습니다. 노드 보정은 한 번의 셰이더 패스로 처리하는 구조라 주변 픽셀을 보는 마스크 블러는 넣지 않았고, 대신 Qualifier 소프트와 창 페더로 경계를 부드럽게 합니다.
- 펜은 베지어 핸들이 아니라 꼭짓점 + 선택적 Catmull-Rom 곡선입니다.
- 스포이드는 미리보기(긴 변 3072px) 픽셀을 읽습니다.
- 다른 사진에 붙여 넣은 그레이드는 되돌리기로 취소되지 않습니다(지금 열린 사진에 붙인 것만 취소 가능). 사진을 넘기면 되돌리기 기록이 비워집니다.
- 일괄 내보내기는 사진을 한 장씩 순서대로 렌더하며, ZIP을 메모리에서 만들기 때문에 수백 장을 한 번에 묶으면 브라우저 메모리가 부족할 수 있습니다. 수십 장 단위로 나눠 내보내세요.
- 필름스트립은 세션 동안만 유지됩니다. 페이지를 새로 고치면 목록과 사진별 그레이드가 사라지므로, 남길 그레이드는 프리셋으로 저장하세요.
- E2E 테스트는 UTF-8 로케일의 브라우저가 필요합니다(`playwright.config.ts`에서 지정). POSIX 로케일에서는 Chromium이 한글 파일 이름을 업로드·다운로드하지 못합니다.
