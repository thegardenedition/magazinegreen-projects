# GREEN GRADE

사진을 올리면 영상 컬러그레이딩 방식(컬러 휠, 노드, 스코프)으로 보정하고 내보내는 웹앱입니다.
정원·조경 사진을 다루는 매거진 에디터를 위해 만들었습니다.
서버 없이 브라우저 안에서만 동작하며, 사진은 외부로 전송되지 않습니다.

> 현재 단계: **Phase 5 완료** (기획한 다섯 단계 모두)
> - Phase 1 — 업로드, WebGL 파이프라인, Before/After 뷰어, Primary 휠, JPG 내보내기
> - Phase 2 — Curves(Custom Y/R/G/B, Hue vs Hue/Sat/Lum, Lum vs Sat), 스코프 4종, 되돌리기/다시 실행
> - Phase 3 — 노드 체인(Serial, 최대 8개), .cube 3D LUT, 프리셋 저장·불러오기, 정원 프리셋 5종 (이후 기본 프리셋 42종 · LUT 라이브러리 50종으로 확장)
> - Phase 4 — HSL Qualifier(스포이드), Window(원형·사각형·그라디언트·펜), 마스크 보기
> - Phase 5 — 여러 장 작업(그레이드 복사·붙여넣기, ZIP 일괄 내보내기), 그레이드 → .cube 내보내기, 정원 프리셋 수치 검증·재조정

## 실행

```bash
cd green-grade
npm install
npm run dev        # http://localhost:5173
npm run build      # 타입체크 + dist/ 정적 빌드 (어느 정적 호스팅에나 올릴 수 있음)
npm test           # 단위 테스트 (기준 수식)
npm run test:e2e   # Playwright E2E (빌드 후 미리보기 서버에서 실행)
```

WebGL2를 지원하는 최신 Chrome, Edge, Safari, Firefox가 필요합니다.

## 색처리 파이프라인

```
 파일 (JPG/PNG/WebP)
   │  createImageBitmap — EXIF 회전 반영, 내장 ICC 프로파일 → sRGB 변환
   ▼
 sRGB 8bit 텍스처 ──────────────── 미리보기: 긴 변 3072px 프록시 + 밉맵
   │                                내보내기: 원본 해상도, 2048px 타일 단위
   ▼  (여기서부터 셰이더 안에서 fp32로 연산)
 ① sRGB → 선형(Linear)
   ┌─ 노드 01 → 노드 02 → … (켜진 노드만, 최대 8개, 아래 ②–⑭를 노드마다 반복) ─┐
 ② 화이트밸런스  Temp / Tint      선형 · 채널 곱 (중립 회색 휘도 유지)
 ③ Offset                         선형 · 2^EV 곱 (노출)
 ④ Gain                           선형 · 채널 곱
 ⑤ 그레이딩 인코딩  p = x^(1/2.4)
 ⑥ Lift            p + lift·(1−p)       흰색 고정, 검정을 들어 올림
 ⑦ Gamma           p^(1/(1+g))          검정·흰색 고정, 중간톤 이동
 ⑧ Contrast/Pivot  (p−pivot)·c + pivot  기본 pivot 0.489 = 18% 그레이
 ⑨ Custom Curves   Y(전 채널) → R/G/B     단조 3차 보간 표, 0–1 밖은 평행 이동
 ⑩ 선형 복귀       x = p^2.4
 ⑪ Saturation      Rec.709 휘도 기준
 ⑫ Hue             회색 축 회전 (무채색 불변)
 ⑬ 색상 커브        그레이딩 인코딩의 Y'CbCr에서
                    Hue vs Hue (색상각 ±60°) · Hue vs Sat (×0–2)
                    Hue vs Lum (루마 ±50%, 무채색 제외) · Lum vs Sat (×0–2)
 ⑭ LUT             선형 → sRGB 코드값 → 3D LUT(3선형 보간) → 선형, 강도만큼 섞음
   ⊕ 마스크         노드 출력 = mix(노드 입력, ②–⑭ 결과, Qualifier × Window)
   └──────────────────────────────────────────────────────────────────────┘
 ⑮ 선형 → sRGB, 1 LSB 삼각 분포 디더(픽셀 좌표 기반) → 8bit
   ▼
 화면 / JPG
```

**왜 두 공간을 나누는가.** 노출, 화이트밸런스, Gain처럼 빛의 양을 곱하는 조작은 선형 공간에서 해야
물리적으로 맞습니다. 반면 Lift, Gamma, Contrast는 사람이 느끼는 밝기 단계를 다루므로 선형 공간에서
적용하면 섀도가 과하게 뭉개집니다. 그래서 톤 조작만 지각적 인코딩(감마 2.4)으로 옮겨 처리하고
다시 선형으로 돌아옵니다.

**컬러 휠.** 휠 위치는 벡터스코프의 U(가로)·V(세로) 축과 같은 방향이며, 휠의 색 편차는 휘도가 정확히
0이 되도록 계산합니다. 휠은 색만, 아래 다이얼은 밝기만 바꿉니다.

**커브.** 모든 커브는 1024칸 표(RGBA32F 텍스처 1024×3)로 구워 셰이더가 읽고, CPU 기준 구현도 같은 표와
같은 선형 보간을 씁니다. 보간은 단조 3차(Fritsch–Carlson)라 점 사이에서 값이 튀어 오르지 않아 계조 반전이나
의도하지 않은 클리핑이 생기지 않습니다. 색상축은 빨강(0)에서 시작해 노랑 → 초록 → 청록 → 파랑 → 마젠타 순이며,
0과 1이 이어진 주기 커브입니다. 색상 커브에 점을 찍으면 양옆(±0.08)에 고정점이 함께 생겨 고른 색 주변만 바뀝니다.

**결정성.** 같은 입력과 같은 보정값은 항상 같은 출력을 냅니다. 디더 노이즈도 픽셀 좌표로 정해지므로
타일 분할 방식과 무관합니다.

기준 수식은 `src/engine/color.ts`·`src/engine/curves.ts`, GLSL은 `src/engine/shaders.ts`에 있으며 둘은 1:1로 대응합니다.

**노드 체인은 한 번의 셰이더 패스.** 노드마다 렌더 패스를 따로 돌리고 중간 결과를 반정밀도(16bit float)
버퍼에 담는 방식 대신, 노드별 값을 길이 8의 배열로 넘겨 셰이더 안에서 노드를 차례로 통과시킵니다. 노드 사이 값이
fp32로 유지되어 밴딩이 생기지 않고, 미리보기·타일 내보내기·스코프가 같은 코드 경로를 씁니다. 대신 노드는 최대 8개입니다.

**LUT.** 노드 보정이 끝난 뒤에 적용합니다. 입력은 sRGB 코드값(0–1, DOMAIN_MIN/MAX를 따름)이며, 3선형 보간은
하드웨어 필터링 대신 셰이더에서 직접 계산해 CPU 기준 구현과 같은 값을 냅니다. LUT 데이터는 RGBA32F 3D 텍스처로
노드 칸마다 하나씩 올라갑니다. 최대 크기는 65³입니다.

## 마스크 (Qualifier · Window)

노드마다 Qualifier 하나와 Window 하나를 둘 수 있고, 노드의 보정은 마스크 값만큼만 들어갑니다.
둘 다 켜면 곱(교집합), 각각 반전할 수 있습니다.

**HSL Qualifier** — 색으로 고르기
- 판정 기준은 **이 노드에 들어오는 색**(앞 노드를 거친 색)이며, 색상 커브와 같은 Y'CbCr(감마 2.4) 공간을 씁니다.
  색상축(빨강 0 → 노랑 → 초록 → 청록 → 파랑 → 마젠타)도 Hue 커브와 같습니다.
- Hue: 중심·폭·소프트 (색상축이 한 바퀴 이어져 빨강 양쪽도 고를 수 있음). 무채색은 색상이 없으므로 Hue 선택에서 빠집니다.
- Sat: 크로마 0.5를 채도 1로 본 낮음·높음·소프트. Lum: 루마 낮음·높음·소프트. 0과 1 끝은 경계로 보지 않습니다.
- **스포이드**: 뷰어를 누르면 주변 5×5 픽셀(미리보기 해상도)을 앞 노드까지 처리한 색으로 범위를 새로 정합니다.
  **+ 더하기**는 기존 범위를 넓혀 새 색까지 포함합니다.

**Window** — 영역으로 고르기
- 원형·사각형: 중심·크기·회전, 페더. 뷰어에서 중심/가로/세로/회전 핸들을 끌어 고칩니다.
- 그라디언트: 시작점에서 1, 끝점에서 0. 기본값은 하늘용(위쪽 → 화면 중간).
- 펜: 뷰어를 눌러 꼭짓점을 찍고(3개부터 적용), 점을 끌어 옮기고 더블클릭으로 지웁니다.
  '부드러운 곡선'을 켜면 꼭짓점을 지나는 Catmull-Rom 곡선으로 이어집니다(최대 64점으로 펼침).
- 좌표는 이미지 기준 0–1, 크기와 페더는 이미지 높이 기준이라 원은 사진 비율과 상관없이 원입니다.

**마스크 보기**(`Shift+H`): 선택 노드의 마스크를 하이라이트(선택 밖을 어둡고 흐리게) 또는 흑백으로 봅니다.

## LUT 라이브러리

LUT 탭의 'LUT 라이브러리'(분류 칩과 검색)에서 누르면 선택 노드에 33³ LUT로 들어갑니다. 파일로 들고 있지 않고
쓸 때 수식으로 계산합니다(`src/engine/lutLibrary.ts`). 다른 프로그램의 LUT 파일을 옮긴 것이 아닙니다.

| 분류 | LUT |
|---|---|
| 유틸리티 7 | 항등 · 반전 · 흑백(휘도) · 흑백(고대비) · 폴스 컬러(노출 확인) · 비디오 레벨 → 풀 레벨 · 풀 레벨 → 비디오 레벨 |
| 카메라 로그 14 | Sony S-Log3/S-Gamut3.Cine · ARRI LogC3/AWG3(EI 800) · Canon Log 3/Cinema Gamut · Panasonic V-Log/V-Gamut · Fujifilm F-Log/F-Gamut · Nikon N-Log/Rec.2020 · HLG/Rec.2020 — 각각 '→ sRGB'(잘림)와 '부드러운 하이라이트' |
| 룩 16 | 필름 프린트(따뜻함·중립) · 슬라이드 필름 · 네거티브(부드러움) · 블리치 바이패스 · 크로스 프로세스 · 틸 & 오렌지 · 데이 포 나이트 · 골든아워 · 매트 블랙 · 파스텔 · 빈티지 브라운 · 세피아 · 셀레늄 흑백 · 쿨 시네마 · 하이 콘트라스트 컬러 |
| 정원 13 | 정원 프리셋 13종을 LUT로 구운 것 (창을 쓰는 노드는 빼고 구움) |

**카메라 로그 LUT.** 제조사가 공개한 로그 곡선과 색역 원색 좌표로 계산합니다: 로그 코드값 → 장면 선형 →
카메라 색역에서 Rec.709/sRGB 원색으로(D65 → D65) → sRGB. 입력은 파일에 저장된 코드값(0–1) 그대로이며,
Canon Log 3만 제조사 수식대로 비디오 레벨 코드값을 받습니다. 18% 회색 코드값(S-Log3 420/1023, LogC3 0.391,
V-Log 0.423, F-Log 0.459, Canon Log 3 0.343, N-Log 약 372/1023, HLG 0.38)이 모두 무채색 sRGB 118±3이 되는지
테스트합니다. '부드러운 하이라이트'는 선형 0.55 위를 기울기가 이어지게 눌러 1에 다가가게 합니다.

**노드 체인에서의 위치.** 카메라 로그 LUT는 첫 노드에(로그를 sRGB로 바꾼 뒤에 다른 보정을 얹도록),
룩 LUT는 마지막 노드에 두는 것이 일반적입니다.

## 정원 프리셋 검증

실제 정원에서 자주 나오는 색 30가지를 견본으로 두고(`src/engine/gardenSwatches.ts` — 잎 7종, 하늘 4종, 흙·돌·나무·벽돌,
꽃 5종, 피부 2종, 단풍 3종, 무채색), 프리셋마다 약속한 효과와 지켜야 할 선을 수치로 정해 테스트합니다
(`tests/unit/gardenPresets.test.ts`, 41개 항목). 회색 계단 반전·새 클리핑·피부 색상 같은 공통 안전선은
기본 프리셋 42종 전체에 적용되며, 분류별로 이름대로의 효과를 내는지는 `tests/unit/presetLibrary.test.ts`가 확인합니다
(예: 녹색 필터 흑백은 잎을 기본 흑백보다 5% 이상 밝게, 노출 +½은 18% 회색의 빛을 ×1.41).
화이트밸런스 보정(따뜻하게·차갑게·그늘·녹색 반사광)과 의도적으로 색을 바꾸는 룩(크로스 프로세스, 틸 & 오렌지 등)은
피부 기준을 완화하거나 제외합니다. 피부까지 함께 옮기는 것이 목적이기 때문입니다.

| 프리셋 | 해야 하는 일 | 하지 말아야 할 일 |
|---|---|---|
| 공통 | — | 회색 계단 반전, 새 클리핑, 피부 색상 ±4° 넘는 이동, 피부 채도 +12% 초과 |
| 신록 | 새순 연두 ↔ 중간 녹색 색상 간격 +4° 이상, 진한 녹색 채도 −5% 이상 | 녹색 채도 상승, 하늘·꽃·피부 색상 ±3° 초과, 그늘 −5% 초과, 돌에 색 끼기 |
| 늦가을 정원 | 밝은 곳 R−B +10 이상, 녹색 채도 −10%·노란 쪽 −2° 이상, 섀도 채도 −5% | 섀도 −15% 초과 |
| 흐린 날 구제 | 미드톤 대비 +8–25%, 위쪽 흐린 하늘 루마 −3%·채도 +10% 이상 | 아래쪽 같은 색에 하늘 보정, 잎 채도 +20%·맑은 하늘 채도 +35% 초과 |
| 매거진 내추럴 | 유채색 평균 채도 −10–22%, 검정 6–14, 흰색 236–248 | 구름 밝은 곳이 222 이하로 죽음 |
| 석재·목재 질감 | 미드톤 대비 +8–20%, 나무·벽돌 채도 +8% 이상 | 밝아짐, 돌에 색 끼기, 그늘 −12% 초과, 녹색 채도 +5% 초과 |

Phase 3의 첫 버전은 이 기준으로 재 보니 41개 중 16개를 통과하지 못했습니다. 신록은 녹색 채도가 오히려
7–12% 올랐고, 흐린 날 구제는 붉은 꽃의 G 채널을 0으로 잘랐습니다. 가장 큰 원인은 색상 위치였습니다.
실제 잎은 순수 초록(0.35)이 아니라 노랑 쪽인 0.24–0.34에, 맑은 하늘은 파랑(0.70)이 아니라 0.61에 있습니다.
지금 값은 견본에서 잰 위치에 Hue 커브 점을 다시 놓고 맞춘 것입니다.

> 견본은 대표 색일 뿐 실제 사진이 아닙니다. 빛, 렌즈, 카메라 프로파일에 따라 실제 잎과 하늘의 위치는 조금씩
> 다르므로, 실제 정원 사진으로 확인하고 필요하면 기준과 값을 함께 고쳐 주세요.

## 여러 장 작업

- **열기**: 여러 장을 한 번에 열거나 끌어다 놓으면 아래 필름스트립에 쌓입니다. 원본은 파일로만 들고 있고
  지금 여는 사진 한 장만 디코딩하므로, 수십 장을 올려도 메모리가 크게 늘지 않습니다.
- **사진마다 그레이드**: 썸네일을 누르면 그 사진으로 넘어가며, 각 사진은 자기 노드 체인을 기억합니다.
  썸네일에는 보정이 반영됩니다.
- **그레이드 복사·붙여넣기**: 지금 사진의 그레이드를 복사(`Ctrl/⌘+C`)하고, 체크박스·`Ctrl/⌘+클릭`·`Shift+클릭`으로
  고른 사진들에 붙여 넣습니다(`Ctrl/⌘+V`). 창 좌표는 이미지 비율 기준이라 크기가 다른 사진에도 같은 자리에 들어갑니다.
- **일괄 내보내기**: 고른 사진들을 각자의 그레이드로 원본 해상도 JPG로 만들어 ZIP 하나로 내려받습니다.
  이름은 `원래이름_GG.jpg`이고, 같은 이름은 `(2)`처럼 번호가 붙습니다.

## 그레이드 → .cube LUT

LUT 탭의 '그레이드를 LUT로 내보내기'는 켜진 노드 전체를 17³·33³·65³ 중 하나의 .cube로 굽습니다. 격자점마다 CPU 기준
구현으로 계산하므로 화면과 같은 수식이며, 33³로 다시 적용했을 때 원래 그레이드와 평균 1 LSB 이하, 최대 3–4 LSB
차이입니다. Qualifier는 색으로 정해지므로 LUT에 그대로 들어갑니다. 창(Window)은 위치 정보라 담을 수 없어,
창이 켜진 노드는 '빼고 굽기'(기본) 또는 '창을 무시하고 화면 전체에 적용' 중에서 고릅니다.

## 스코프

```
 프록시 ─▶ 분석 렌더 (가로 512px, 보정 적용, 디더 없음) ─┬─▶ 점 산포 + 가산 합성 (GPU)
                                                     │     Waveform  : x = 이미지 가로, y = 루마
                                                     │     Parade    : R·G·B 3분할
                                                     │     Vector    : Cb(가로)·Cr(세로)
                                                     │     → 반정밀도 누적 버퍼 → 로그 톤으로 표시
                                                     └─▶ 픽셀 읽기 → Histogram·클리핑 비율 (정확한 개수)
```

- 스코프는 뷰어와 별도의 WebGL2 컨텍스트에서 돌아가며, 보정값이 바뀔 때마다 다시 계산합니다.
- 측정 대상은 **출력 sRGB 코드값**입니다. 0–100 IRE는 0–255에 대응합니다.
- 벡터스코프의 방향은 컬러 휠과 같습니다(빨강 왼쪽 위, 파랑 오른쪽). 75% 컬러바 목표점과 스킨톤 라인(점선)을 표시합니다.
- 하단 표시줄: 한 채널이라도 255에 닿은 픽셀(하이라이트)과 0에 닿은 픽셀(섀도)의 비율. 0.1%를 넘으면 붉게 경고합니다.

## 되돌리기

노드 체인 전체(노드 추가·삭제·순서·이름, Primary, Curves, LUT, 노드 on/off, 프리셋 적용)가 기록 대상입니다. 드래그나 연속 입력은 손을 멈춘 뒤 0.25초가 지나면 한 단계로
묶여 기록되며, 최대 200단계까지 보관합니다.

## 현재 한계

- 카메라 로그 LUT는 공개 수식으로 계산했고 18% 회색과 구간 연속성을 테스트했지만, 실제 카메라 로그 영상으로는 확인하지 못했습니다. 비디오 레벨/데이터 레벨 해석은 프로그램마다 달라, 결과가 뿌옇거나 과하게 진하면 유틸리티의 '비디오 레벨 → 풀 레벨'을 앞 노드에 두세요.

- 100% 이상으로 확대하면 프록시(긴 변 3072px)가 보이므로 원본보다 덜 선명합니다. 내보내기는 항상 원본 해상도입니다.
- JPG에 ICC 프로파일을 넣지 않습니다. 출력은 sRGB 기준이며, 대부분의 웹·인쇄 입고 환경에서 sRGB로 해석됩니다.
- GPU 최대 텍스처 크기(대개 8192 또는 16384px)를 넘는 사진은 아직 내보낼 수 없습니다.
- 노드는 Serial 8개까지입니다. Parallel·Layer Mixer 노드는 없습니다.
- LUT는 sRGB 사진 기준으로 만든 것을 전제로 합니다. 로그(Log) 영상용 LUT를 넣으면 색이 크게 틀어집니다.
- 내 프리셋은 브라우저 저장소(localStorage)에 있어 브라우저를 바꾸거나 사이트 데이터를 지우면 사라집니다. 오래 보관할 프리셋은 JSON으로 내보내세요.
- 정원 프리셋은 대표 색 견본으로 수치 검증했지만, 실제 정원 사진으로는 아직 확인하지 못했습니다(작업 환경에서 외부 사진을 받을 수 없었음).
- 스코프는 가로 512px 분석본으로 계산합니다. 머리카락처럼 아주 작은 영역의 클리핑은 비율에 덜 잡힐 수 있습니다.
- 스코프 갱신마다 GPU에서 분석 픽셀을 한 번 읽어옵니다(약 17만 픽셀). 히스토그램을 정확한 개수로 세기 위한 선택이며, 일반적인 노트북에서 슬라이더 조작에 지장이 없는 수준입니다.
- 커브 점을 숫자로 직접 입력하는 기능, 뷰어에서 색을 찍어 색상 커브에 점을 만드는 기능은 아직 없습니다.
- 노드당 창은 하나입니다. 여러 창을 겹치려면 노드를 나눠 쓰세요.
- 마스크 다듬기(블러, 클린 블랙/화이트)와 트래킹은 없습니다. 한 번의 셰이더 패스로 처리하는 구조라 주변 픽셀을 보는 블러는 넣지 않았고, 대신 Qualifier 소프트와 창 페더로 경계를 부드럽게 합니다.
- 펜은 베지어 핸들이 아니라 꼭짓점 + 선택적 Catmull-Rom 곡선입니다.
- 스포이드는 미리보기(긴 변 3072px) 픽셀을 읽습니다.
- 다른 사진에 붙여 넣은 그레이드는 되돌리기로 취소되지 않습니다(지금 열린 사진에 붙인 것만 취소 가능). 사진을 넘기면 되돌리기 기록이 비워집니다.
- 일괄 내보내기는 사진을 한 장씩 순서대로 렌더하며, ZIP을 메모리에서 만들기 때문에 수백 장을 한 번에 묶으면 브라우저 메모리가 부족할 수 있습니다. 수십 장 단위로 나눠 내보내세요.
- 필름스트립은 세션 동안만 유지됩니다. 페이지를 새로 고치면 목록과 사진별 그레이드가 사라지므로, 남길 그레이드는 프리셋으로 저장하세요.
- E2E 테스트는 UTF-8 로케일의 브라우저가 필요합니다(`playwright.config.ts`에서 지정). POSIX 로케일에서는 Chromium이 한글 파일 이름을 업로드·다운로드하지 못합니다.
