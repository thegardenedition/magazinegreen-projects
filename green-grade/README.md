# GREEN GRADE

사진을 올리면 영상 컬러그레이딩 방식(컬러 휠, 노드, 스코프)으로 보정하고 내보내는 웹앱입니다.
정원·조경 사진을 다루는 매거진 에디터를 위해 만들었습니다.
서버 없이 브라우저 안에서만 동작하며, 사진은 외부로 전송되지 않습니다.

> 현재 단계: **Phase 1** — 업로드, WebGL 파이프라인, Before/After 뷰어, Primary 휠, JPG 내보내기

## 실행

```bash
cd green-grade
npm install
npm run dev        # http://localhost:5173
npm run build      # 타입체크 + dist/ 정적 빌드 (어느 정적 호스팅에나 올릴 수 있음)
npm test           # 단위 테스트 (기준 수식)
npm run test:e2e   # Playwright E2E (빌드 후 미리보기 서버에서 실행)
```

WebGL2를 지원하는 최신 Chrome, Edge, Safari, Firefox가 필요합니다.

## 색처리 파이프라인

```
 파일 (JPG/PNG/WebP)
   │  createImageBitmap — EXIF 회전 반영, 내장 ICC 프로파일 → sRGB 변환
   ▼
 sRGB 8bit 텍스처 ──────────────── 미리보기: 긴 변 3072px 프록시 + 밉맵
   │                                내보내기: 원본 해상도, 2048px 타일 단위
   ▼  (여기서부터 셰이더 안에서 fp32로 연산)
 ① sRGB → 선형(Linear)
 ② 화이트밸런스  Temp / Tint      선형 · 채널 곱 (중립 회색 휘도 유지)
 ③ Offset                         선형 · 2^EV 곱 (노출)
 ④ Gain                           선형 · 채널 곱
 ⑤ 그레이딩 인코딩  p = x^(1/2.4)
 ⑥ Lift            p + lift·(1−p)       흰색 고정, 검정을 들어 올림
 ⑦ Gamma           p^(1/(1+g))          검정·흰색 고정, 중간톤 이동
 ⑧ Contrast/Pivot  (p−pivot)·c + pivot  기본 pivot 0.489 = 18% 그레이
 ⑨ 선형 복귀       x = p^2.4
 ⑩ Saturation      Rec.709 휘도 기준
 ⑪ Hue             회색 축 회전 (무채색 불변)
 ⑫ 선형 → sRGB, 1 LSB 삼각 분포 디더(픽셀 좌표 기반) → 8bit
   ▼
 화면 / JPG
```

**왜 두 공간을 나누는가.** 노출, 화이트밸런스, Gain처럼 빛의 양을 곱하는 조작은 선형 공간에서 해야
물리적으로 맞습니다. 반면 Lift, Gamma, Contrast는 사람이 느끼는 밝기 단계를 다루므로 선형 공간에서
적용하면 섀도가 과하게 뭉개집니다. 그래서 톤 조작만 지각적 인코딩(감마 2.4)으로 옮겨 처리하고
다시 선형으로 돌아옵니다.

**컬러 휠.** 휠 위치는 벡터스코프의 U(가로)·V(세로) 축과 같은 방향이며, 휠의 색 편차는 휘도가 정확히
0이 되도록 계산합니다. 휠은 색만, 아래 다이얼은 밝기만 바꿉니다.

**결정성.** 같은 입력과 같은 보정값은 항상 같은 출력을 냅니다. 디더 노이즈도 픽셀 좌표로 정해지므로
타일 분할 방식과 무관합니다.

기준 수식은 `src/engine/color.ts`, GLSL은 `src/engine/shaders.ts`에 있으며 둘은 1:1로 대응합니다.

## 단축키

| 키 | 동작 |
|---|---|
| `Ctrl/⌘ + O` | 사진 열기 (또는 창에 끌어다 놓기) |
| `Ctrl/⌘ + E` | JPG 내보내기 |
| `S` | Before/After 분할 켜기·끄기 (분할선은 드래그로 이동) |
| `B` | 원본 보기 |
| `Ctrl/⌘ + D` | 노드 01 켜기·끄기 |
| `F` / 뷰어 더블클릭 | 화면 맞춤 |
| `1` | 100% (원본 픽셀 1:1) |
| 마우스 휠 / 드래그 | 확대·축소 / 이동 |
| `Shift` + 휠·다이얼 드래그 | 미세 조정 (1/4 속도) |
| 더블클릭 | 휠: 색 리셋 · 다이얼: 밝기 리셋 · 휠 제목: 전체 리셋 · 슬라이더: 리셋 |

수치 칸은 클릭해 직접 입력하고 `Enter`로 반영, `Esc`로 취소합니다. 휠의 R/G/B 칸에 입력하면 휠 위치와 다이얼이 함께 맞춰집니다.

## 테스트

- `tests/unit/grade.test.ts` — 기준 수식. 기본값에서 0–255 전 구간 무변화, Gain 2.0에서 sRGB 118 → 162, Lift 0.1에서 검정 → 13, Hue 120°에서 빨강 → 초록 등 알려진 입력·출력 확인.
- `tests/e2e/phase1.spec.ts`
  - GPU 셰이더 결과가 기준 수식과 1 LSB 이내로 일치 (216색 × 보정 조합 4종)
  - 2048px 타일 경계를 넘어도 픽셀 위치가 정확
  - 디더링 결과의 결정성
  - 업로드 → 휠·다이얼·슬라이더 보정 → JPG 내보내기 → 해상도와 밝기 변화 확인
  - 보정 없이 내보내면 원본과 같은 색
  - 13.5MP 이미지의 원본 해상도 내보내기
  - 단축키

## Phase 1의 한계

- 100% 이상으로 확대하면 프록시(긴 변 3072px)가 보이므로 원본보다 덜 선명합니다. 내보내기는 항상 원본 해상도입니다.
- JPG에 ICC 프로파일을 넣지 않습니다. 출력은 sRGB 기준이며, 대부분의 웹·인쇄 입고 환경에서 sRGB로 해석됩니다.
- GPU 최대 텍스처 크기(대개 8192 또는 16384px)를 넘는 사진은 아직 내보낼 수 없습니다.
- 노드 간 중간 버퍼(RGBA16F/32F)는 노드 체인이 생기는 Phase 3에서 도입합니다. 지금은 한 번의 셰이더 패스 안에서 fp32로 처리합니다.
- 스코프, 커브, Undo/Redo는 Phase 2, 프리셋·LUT는 Phase 3, Qualifier·Window는 Phase 4입니다.
